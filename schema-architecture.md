# Smart Clinic Management System – Architecture Design

## Section 1: Architecture Summary

The Smart Clinic Management System is a Spring Boot application built on a three-tier architecture: a presentation layer, an application layer, and a data layer. The presentation layer has two entry styles. The Admin and Doctor dashboards are server-rendered HTML pages built with Thymeleaf and served by Spring MVC controllers, while the remaining modules (patient flows, appointments, prescriptions) are exposed as RESTful APIs that return JSON to the HTML/CSS/JavaScript frontend or any other client. Both controller types delegate to a shared service layer that holds the business rules, such as validating appointment slots, checking doctor availability, and enforcing role-based access through JWT tokens. The service layer talks to two databases through Spring Data repositories: MySQL, accessed through Spring Data JPA, stores the structured, relational data (admins, doctors, patients, and appointments) as JPA entities, and MongoDB, accessed through Spring Data MongoDB, stores flexible, document-shaped data such as prescriptions as document models. Keeping controllers thin and routing everything through one service layer keeps the business logic in one place, makes it testable, and lets the two presentation styles share the same rules. The whole application is packaged as a Docker container and checked by GitHub Actions CI workflows.

## Section 2: Numbered Flow of Data and Control

1. **User interaction** – A user opens a Thymeleaf page such as the Admin Dashboard or Doctor Dashboard, or the JavaScript frontend sends an HTTP request to a REST endpoint (for example, a patient booking an appointment).
2. **Controller routing** – Spring routes the request by URL path and HTTP method to the matching controller: a Thymeleaf `@Controller` for server-rendered dashboards, or a `@RestController` for JSON API calls. The controller validates the incoming data and the user's JWT token.
3. **Service layer** – The controller calls the relevant service (for example, `AppointmentService` or `DoctorService`), which applies the business rules, such as checking that a doctor is available at the requested time or that the caller's role is allowed to perform the action.
4. **Repository layer** – The service calls the appropriate Spring Data repository: a JPA repository for MySQL-backed data (admins, doctors, patients, appointments) or a MongoDB repository for prescription documents.
5. **Database access** – The repository translates the call into a query and runs it against the database: SQL through Hibernate/JPA for MySQL, or a document query through the MongoDB driver.
6. **Model binding** – The query results are mapped back into Java objects: `@Entity` classes for MySQL rows and `@Document` classes for MongoDB documents. The service layer then returns these models (or DTOs built from them) to the controller.
7. **Response to the user** – For MVC requests, the controller adds the models to the view and Thymeleaf renders them into an HTML page. For REST requests, Spring serializes the models or DTOs to JSON and sends them back in the HTTP response, where the frontend JavaScript displays them.
